## Setup

- **Model:** `qwen38` (Qwen3.8 27B, layer split across two GPUs, q8_0 KV) behind llama-swap on a
  home GPU box, reached over the LAN. `ork doctor` was all green (tool calling on the first try,
  ~51 t/s). The `qwen38-fast` preset crashed with CUDA out-of-memory on its first request; doctor
  caught it (and got a better hint for it, order 3).
- **Where `ork` ran:** a Windows laptop without the MSVC build tools, so Rust can't link there
  (#19). `ork` ran in a `rust:1.99.1` container with the repo mounted and a shared
  `CARGO_TARGET_DIR` (which commands now get, #30), so the grunt's `cargo` checks worked.
- **The chief** was Claude Code: it wrote the orders, read the reports, reviewed every diff and
  applied the work onto the `dogfood/v0.1` branch.
- `context_tokens` 65536; the other limits at their defaults (40 turns, 2 repairs, 20 minutes).

## What went right

- **The grunt verified before it finished.** In every order it ran the checks' commands itself
  (`cargo fmt`, `cargo test`, `cargo clippy`) before calling `finish`, so the checks passed the
  first time. Telling it to run `cargo fmt` before `finish` in the order's context worked every
  time.
- **Errors as results worked on a real model.** Order 2 tried `cargo fmt && cargo clippy`; the
  policy refused the `&`, and the grunt ran the two separately on its next turn. Order 6 tried
  `which rg`, was refused (not allowed), and moved on.
- **Tool calling was solid:** no malformed calls, no guard gave up. One text-only reply in 94 turns
  (order 3), nudged back.
- The diffs read like code from this repo: its naming, doc comments and test style.

## What went wrong, and what changed

1. **Passing checks didn't mean correct code.** Order 2's line-number parser had an off-by-one:
   one-digit line numbers weren't found. Its tests all used `12`, so they passed. Caught in the
   chief's review of the diff and fixed by order 2b, whose order named the edge cases.
   → **The guide now says so:** the checks prove only what the tests test, so name the edge cases.
2. **`git grep` read the patterns as basic regexes**, the opposite of ripgrep for `(` and `\(`.
   Order 4's patterns (`call\(`, `a|prepare\(`) failed five times. → **Order 6: `git grep -E`.**
3. **Long thinking costs minutes.** Order 3 spent 13k output tokens on two turns, most of it
   Qwen's reasoning (stripped from the history, but still generated), about 2½ minutes at 47 t/s.
   → The prompt asks for short thinking and small steps; a per-role switch for thinking is #33.
4. **A shell habit:** `&&` between commands (order 2). → The prompt now says `run` takes one
   command, without a shell.
5. **Read-only orders resend a lot.** Order 4: 25 turns, 590k tokens in, as the context grows with
   every file read. Fine at this speed (llama.cpp caches the prompt), but it's what a token budget
   (#24) and stubbing big arguments (#23) are for.
6. **The merge commit repeated the job commit's subject in full.** → `ork apply` now cuts it at 72
   characters, like the job commit.
7. **Events have no timestamps,** so a job's duration can't be read back from its log (this table
   added up the parts instead). The UI will need them (#31). → #32.
8. **Setup, not ork:** the bind-mounted checkout showed every file as changed to Linux git because
   `core.filemode` was on (fixed for this checkout); `CARGO_TARGET_DIR` wasn't passed to commands
   (#30).
